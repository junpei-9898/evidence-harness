# ALLOWLIST.md — 公開ファイル許可一覧

本リポに入れてよいもの／入れてはならないものを機械検査（`scripts/leak_check.py`）と併せて定める。
public 化の前に本表と漏出検査を再実行する。

## 入れてよい

- 研究側から移植したコード（`docs/PORTING.md` の部品対応表に載るもの）とそのテスト。
- **合成**の差分試験 fixture（`tests/differential/fixtures/`）。本文・パス・質問は合成生成器の出力のみ。
- 合成診断バッテリー（`battery/`）: lookup 型生成器（単一 lookup／二ファイル結合／優先順位／alias／index）・探索用合成リポ生成器・対照（証拠なし／紛らわしい出典／名前が正答）・counter-default／fictional 型の供給証拠診断。gold は採点側のみ。
- レシピ（`recipes/`）: 公開重み（Qwen3.6-35B-A3B base NVFP4／Mercor NVFP4）の vLLM 起動フラグ・no-MTP・gpu util・並列上限・hang/crash 開示。重みそのものは含めない。
- 主張表（`docs/CLAIMS.md`）: 公開可能な方法と集計値・登録ラベルと判断採用の併記。
- 非公開 suite の **sha256 照合値**（値のみ・中身は入れない）。

## 入れてはならない

- 非公開 suite の本文・質問・gold・パス（実リポ由来の質問 suite・関節健診 suite・供給証拠 items を含む）。
- 実リポ由来の transcript・保存応答・ログ（研究側の非公開ディレクトリ配下の一切）。
- 研究側の内部識別子: 作業項目番号・研究側のファイル名やモジュールパス・研究側リポの commit hash・研究側の独自 HTTP ヘッダ名・研究プロジェクト名。移植の追跡は研究側の完全台帳で行う。
- 作者以外のプロジェクト名・顧客名・組織名、ホームディレクトリ配下の絶対パス、メールアドレス。
- モデル重み・アダプタ・チェックポイント。
- 研究側の測定結果を本リポの実績として書き換えた記述（`CLAIMS.md` の規律）。

## 機械検査（`scripts/leak_check.py`）

- 平文パターン: ホーム配下の絶対パス・研究側の非公開ディレクトリ名・研究側の作業項目番号や内部モジュールパスの命名・研究プロジェクト名・メールアドレス（正規表現は `scripts/leak_check.py` を正とする）。
- 秘匿トークン: 実リポ名等は sha256 化した denylist で照合（平文を本リポに置かない）。
- 対象: git 管理下の全テキストファイル。CI で毎回実行。失敗＝commit 不可。
